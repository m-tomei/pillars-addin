# 02. 病薬表示機能仕様（F-02）

## 1. 目的

命理正宗（張楠）の病薬説に基づき、命式中の **病（害をなす神）** と **薬（その害を除く一字／五行）** を算出し、ユーザーに表示する。

> 病 = 八字中で害をなしている神  
> 薬 = その害を取り去るもの  

根拠:

- `資料/病薬説_初心者から中級者向け解説.md`
- `資料/喜忌篇_初心者から中級者向け解説.md`
- `資料/継善篇_初心者から中級者向け解説.md`
- `資料/気象篇_初心者から中級者向け解説.md`

照合結果: [07_病薬ロジック資料照合レビュー.md](./07_病薬ロジック資料照合レビュー.md)  
※ 現行 `ByoyakuCalculator` は格局別病薬の骨格のみ。気象・喜忌・継善の取り込みは本仕様の必須要件とする。

## 2. 前提条件

| 条件 | 内容 |
|------|------|
| オプション | F-03 の「病薬表示」が ON |
| 本体結果 | F-01 の命式算出が成功していること |
| 理論系 | 子平／四柱推命（日干主体）。禄命法（年柱中心・通変星不使用）とは混同しない |

## 2.1 看命パイプライン（必須順序）

病薬を出す前に、資料どおり次の順序をロジック契約とする。

```text
日干（喜忌）
  → 月令提綱（喜忌）
  → 気象規模（気象篇: 寒暖・燥湿・清濁）
  → 主軸＝守るべき用神（継善篇）
  → 用神損傷の列挙（継善篇）
  → 從重者論＋四病四薬＋格局別病薬（病薬説）
  → 喜忌ラベル確定（薬側＝喜、病側＝忌）
```

| 篇 | 取り込み内容 |
|----|--------------|
| 喜忌篇 | 日干為主・月令提綱・透干＞蔵干の重み。最終的な喜／忌ラベル |
| 継善篇 | 格局の柱（用神）を定め、損傷（破）を病候補にする |
| 気象篇 | 病薬前に寒暖・燥湿を評価し、調候方向を薬候補へ反映。清濁は初版では `不明` とする |
| 病薬説 | 病／薬の確定、四病四薬、病薬バランス |

## 3. 理論要件（命理正宗）

実装・表示が満たすべき中核概念。

### 3.1 基本対応（主軸 → 病 → 薬）

| 主軸 | 病 | 薬 |
|------|----|----|
| 財 | 比肩（比劫） | 官殺 |
| 食神傷官 | 印綬 | 財 |
| 官殺 | 傷官 | 財 |
| 印綬 | 財 | 比劫 |

※ 前半2例は原文の直接例、後半2例は理論的整理（解説資料準拠）。

### 3.2 從重者論

1. 日干を確認する  
2. 月令を起点に重い五行を見る（月令ブースト必須。均等加重のみは不可）  
3. 同五行をまとめて勢力として扱う  
4. 最も重い害を病として優先する  
5. 算出した最重五行は、四病分類・病候補に実際に接続する（算出して捨てない）

### 3.2b 気象（必須）

病薬算出の前に、少なくとも次を評価する。

| 軸 | 例 |
|----|-----|
| 寒暖 | 寒 / 涼 / 温 / 熱 |
| 燥湿 | 燥 / 中 / 湿 |
| 清濁 | 初版は `不明` 固定。清／濁の判定は根拠と校正例を追加した後の拡張とする |

極端な偏りは調候不足として病候補に含め、薬は十神薬と調候五行を突合して決める。

### 3.2c 継善・用神損傷（必須）

1. 格局から主軸（守るべき用神カテゴリ）を立てる  
2. その主軸を壊す要素を `breaks[]` として列挙する  
3. 格局別ルール照合は、この損傷リストを入力として行う  

### 3.3 四病・四薬（現行エンジンを拡張）

現行 `ByoyakuCalculator` の分類を土台とし、気象・從重・用神損傷を加味して拡張する。

| 四病 | 概要 |
|------|------|
| 雕 | 用神に対する対立要素が欠ける |
| 枯 | 根が弱い／浮く |
| 旺 | 特定五行・勢力の過旺 |
| 弱 | 身弱など力不足 |

| 四薬 | 概要 |
|------|------|
| 損 | 過旺を削る |
| 益 | 不足を補う |
| 生 | 生じて助ける |
| 長 | 長養・伸長 |

### 3.4 格局別具体病薬

`data/kakkyoku_rules.json` の格局別 `diseases` / `defaultDisease` により、具体的な病名・薬名・理由を得る。  
複数条件がマッチした場合は **複数診断（diagnoses配列）** として扱う（現行仕様を維持）。

## 4. 算出仕様

### 4.1 公開API（v2契約）

```text
ByoyakuCalculator.diagnose({
  kakkyokuResult,
  strengthResult,
  fortuneResult,
  tsuuhenResult,
  gouChuuResult?,  // 合化反映用。任意
  kishouResult,    // 必須
  keizenResult     // 必須
}) → ByoyakuResult
```

- v2では気象・継善の入力漏れを防ぐため、object引数を正規APIとする。
- 既存の位置引数APIは実装移行中の互換アダプタに限り許容し、新規呼び出しでは使用しない。
- 後方互換の対象は代表診断の `disease` / `medicine` / `summary` とする。表示順の `diagnoses[0]` と同一とは限らない。

### 4.2 戻り値（表示に必要なフィールド）

```text
ByoyakuResult {
  disease:   { name, element, tenGod, severity }   // 先頭診断（後方互換）
  medicine:  { name, element, tenGod, exists, location }
  summary:   string
  fourDisease:  '雕'|'枯'|'旺'|'弱'
  fourMedicine: '損'|'益'|'生'|'長'|null
  fourDiseaseElement: string|null
  fourMedicineElement: string|null
  treatmentMode: '琢'|null  // 雕の処置。四薬とは分離
  treatmentElements: string[]
  diagnoses: [
    {
      disease:  { name, element, tenGod, severity }
      medicine: { name, element, tenGod, exists, location }
      reason:   string
    },
    ...
  ]
  kishou:    KishouResult
  keizen:    { pillar, breaks, summary }
  balance:   { label, diseaseScore, medicineScore, reading }
  kiki:      { ki, ji, note }
}
```

気象由来の病は「不足している薬五行」と「病の五行」を混同しない。害をなす五行を一意に特定できない場合、`disease.element` は `null` とし、`causeElements`（原因側）と `deficientElements`（不足側）を別フィールドで表す。

### 4.3 内部依存（ユーザー向け機能としては非公開でも可）

病薬算出のため、オプションON時のみ以下を実行する。

| 依存 | モジュール | 理由 |
|------|------------|------|
| 身旺弱 | DayMasterStrengthAssessor | 四病分類・格局別ルール分岐 |
| 格局 | KakkyokuCalculator | 主軸（用神カテゴリ）と具体病薬ルール |
| 合冲（推奨） | GouChuuCalculator | 合化後五行の分布反映 |

※ これらは **F-02 の内部前処理** であり、本変更では「合冲分析」「格局診断」を独立オプション化しない。

## 5. 表示仕様（要約）

詳細は [05_UI表示仕様.md](./05_UI表示仕様.md)。

必須表示項目:

| 項目 | 必須 |
|------|------|
| 病名 | ○ |
| 四病分類 | ○ |
| 重症度（軽／中／重） | ○ |
| 病の五行・十神 | △（取得できる場合） |
| 薬名 | ○ |
| 四薬分類 | ○ |
| 薬の五行 | △ |
| 理由（reason） | ○ |
| 命式中に薬があるか／位置 | ○ |
| 複数診断 | ○（2件以上時） |

推奨の補助表示（コンパクト）:

| 項目 | 理由 |
|------|------|
| 身旺弱ラベル | 病薬判断の前提が分かる |
| 格局名（成格／破格） | 具体病薬ルールの根拠 |

## 6. エラー・例外

| 状況 | 挙動 |
|------|------|
| 命式算出失敗 | 病薬は実行しない。本体エラーを表示 |
| 病薬依存データ不足 | CalculationError。ユーザー向けに「病薬判定に失敗」を表示。本体命式は維持してよい |
| 診断0件になりえない場合 | 現行どおり defaultDisease で最低1件を返す方針を維持 |

## 7. 受け入れ基準（病薬オプションON時）

1. 病と薬が少なくとも1組表示される  
2. 四病・四薬ラベルが出る  
3. 薬の有無（命式内／行運で補う）が分かる  
4. 複数マッチ時は複数ブロックで表示される  
5. オプションをOFFに戻すと病薬ブロックが消え、再計算時も病薬パイプラインが走らない
