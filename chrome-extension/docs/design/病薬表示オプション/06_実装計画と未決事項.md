## 3. 決定事項

### D-01. 大運吉凶（DaiunHyouka）の扱い

| 選択肢 | 内容 |
|--------|------|
| A | 病薬OFF時は実行しない。病薬ON時も本変更では非表示のまま（既存トグル依存） |
| B | 病薬ON時は従来どおり評価まで実行し、既存トグルで詳細表示 |
| C | 大運吉凶も別オプション化する（スコープ拡大・非推奨） |

**設計側の推奨: B**（既存挙動を壊しにくい）
ただし病薬OFF時は必ずスキップする。

**決定: B。**

### D-02. 合冲セクションの表示

| 選択肢 | 内容 |
|--------|------|
| A | 病薬パイプライン内でのみ計算し、**合冲UIは出さない**（内部利用のみ） |
| B | 病薬ON時は現行どおり合冲セクションも出す |
| C | 合冲も独立オプション（スコープ拡大） |

**設計側の推奨: A**（本変更の主題を病薬に絞る）

**決定: A。合冲は内部入力としてのみ利用し、本変更では合冲UIを表示しない。**

### D-03. 格局・身旺弱のユーザー表示

| 選択肢 | 内容 |
|--------|------|
| A | 病薬セクション内に補助情報として表示（推奨） |
| B | 完全非表示（内部計算のみ） |
| C | 別セクションで常時表示 |

**設計側の推奨: A**

**決定: A。**

### D-04. スイッチ変更時の再計算

| 選択肢 | 内容 |
|--------|------|
| A | 自動再計算 |
| B | 「再計算してください」と案内のみ |
| C | 表示だけ切り替え（計算は常時両方）← **不採用** |

**設計側の推奨: A**

**決定: A。入力が有効で計算済みの場合のみ自動再計算し、未入力・無効入力ではフラグ更新だけを行う。**

### D-05. オプション永続化

| 選択肢 | 内容 |
|--------|------|
| A | セッション内のみ |
| B | `chrome.storage.local` で永続化 |

**設計側の推奨: 初回は A、必要なら B を追加**

**決定: A。初版ではセッション内のみ。`storage` 権限は追加しない。**

### D-06. デフォルト値

| 選択肢 | 内容 |
|--------|------|
| A | OFF（命式のみ）← 本設計の方針 |
| B | ON（現行に近い） |

**設計側の推奨: A**

**決定: A。**

### D-07. 気象と格局別病薬が矛盾した時の優先

| 選択肢 | 内容 |
|--------|------|
| A | 気象（調候）を常に最優先の病／薬とする |
| B | 継善の用神損傷を最優先し、気象は副病として併記（推奨） |
| C | 格局ルールのみ（気象は表示だけ）← 不採用 |

**設計側の推奨: B**（07レビュー 4.4 統合ルール）

**決定: B。用神損傷を主病、気象を副病とする。主病がなく気象偏りだけが重大な場合に限り、気象診断を先頭表示できる。**

### D-08. 気象の清濁を初版で実装するか

| 選択肢 | 内容 |
|--------|------|
| A | 寒暖・燥湿のみ初版。清濁は P2 |
| B | 清濁も簡易ルールで初版から入れる |

**設計側の推奨: A**

**決定: A。初版は `clarity: '不明'` 固定とし、清／濁を推測表示しない。**

## 4. リスク

| リスク | 影響 | 緩和 |
|--------|------|------|
| 病薬が格局依存のため、病薬ONで格局計算が必須 | 計算時間増 | ON時のみ実行 |
| UIから格局表現を消すと理由が分かりにくい | 理解低下 | 補助表示（D-03-A） |
| 既存ユーザーが常時病薬表示に慣れている | 戸惑い | ガイド更新・スイッチを目立たせる |
| 大運吉凶と病薬の依存 | OFF時に吉凶が空になる | D-01 で明示 |
