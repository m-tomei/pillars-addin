# 03. 補正アルゴリズム詳細

## 1. 入力

| フィールド | 型 | 説明 |
|------------|-----|------|
| year, month, day | number | 入力暦日 |
| hour, minute | number | 入力時計時刻（本処理は時あり時のみ。分欠落は呼出前に0へ正規化） |
| offsetMinutes | number | 時差。整数。範囲 -1439‥1439（±23:59） |
| prefectureCode | string \| null | 都道府県コード。null なら経度補正なし |

経度マスタはサービスコンストラクタで保持する（correct 引数には渡さない）。

## 2. 時差（C）

```
offsetMinutes = sign * (tzHour * 60 + tzMinute)
```

- UI空欄相当: `offsetMinutes = 0`
- 符号: 出生地時計を JST に合わせる加算分が正

## 3. 地方平均時（A）

```
lon = masterByCode.get(code).longitudeEast
longitudeOffsetMinutes = Math.round(4 * (lon - master.referenceMeridianEast))
```

- `referenceMeridianEast === 135.0`
- 未選択: `longitudeOffsetMinutes = 0`、`prefecture = null`
- 東京 139.6917 → **+19分**

不正コードは InputManager で排除済み想定。サービスが受け取った場合は内部不整合として例外。

## 4. 合成と正規化（正式方式）

**契約:** すべての年月日時分は **JST暦の数値** として扱う。  
正規アルゴリズムから OSタイムゾーン依存の `new Date(y, m-1, ...)` による加減算は除外する。

```
totalOffsetMinutes = offsetMinutes + longitudeOffsetMinutes
corrected = DateUtils.addMinutes(year, month, day, hour, minute, totalOffsetMinutes)
```

### 4.1 分加算の定義（JavaScript）

```js
function floorDiv(a, b) {
  return Math.floor(a / b);
}

function mod(a, b) {
  return ((a % b) + b) % b; // 正の剰余
}

function addMinutes(y, m, d, h, mi, deltaMinutes) {
  const minutesOfDay = h * 60 + mi + deltaMinutes;
  const daysDelta = floorDiv(minutesOfDay, 1440);
  const minuteOfDay = mod(minutesOfDay, 1440);
  const hour2 = Math.floor(minuteOfDay / 60);
  const minute2 = minuteOfDay % 60;
  const date2 = addDays(y, m, d, daysDelta); // グレゴリオ暦、月末/年末/閏日を正しく跨ぐ
  return { ...date2, hour: hour2, minute: minute2 };
}
```

### 4.2 日加算の定義（JavaScript・OS TZ非依存）

入出力は数値の `{ year, month, day }` のみ。`new Date(...)` は使わない。

```js
function isLeapYear(year) {
  return (year % 4 === 0 && year % 100 !== 0) || year % 400 === 0;
}

function daysInMonth(year, month) {
  const mdays = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31];
  if (month === 2 && isLeapYear(year)) return 29;
  return mdays[month - 1];
}

function addDays(year, month, day, deltaDays) {
  let y = year, m = month, d = day;
  let n = deltaDays;
  if (n >= 0) {
    d += n;
    while (d > daysInMonth(y, m)) {
      d -= daysInMonth(y, m);
      m += 1;
      if (m > 12) { m = 1; y += 1; }
    }
  } else {
    while (n < 0) {
      d -= 1;
      n += 1;
      if (d < 1) {
        m -= 1;
        if (m < 1) { m = 12; y -= 1; }
        d = daysInMonth(y, m);
      }
    }
  }
  return { year: y, month: m, day: d };
}
```

### 4.3 節入り比較の時刻契約（確定・N-01）

比較は **絶対時刻（epoch millis）** で行う。OSローカルTZの `new Date(y, m-1, ...)` および ISO の `+09:00` 削除は禁止。

```js
const JST_OFFSET_MS = 9 * 60 * 60 * 1000;

/** JST暦の数値 → UTC epoch */
function toJstEpochMillis(year, month, day, hour = 0, minute = 0) {
  return Date.UTC(year, month - 1, day, hour, minute) - JST_OFFSET_MS;
}

/** 節気ISO（例 1900-02-05T11:00:00+09:00）→ Date（offsetを削除しない） */
function parseISOString(isoString) {
  return new Date(isoString); // Date.parse が +09:00 を解釈
}

/** 節入り比較（前後判定）。暦日へ丸めない */
function isAfterOrEqualSolarTerm(y, m, d, h, mi, isoString) {
  return toJstEpochMillis(y, m, d, h, mi) >= parseISOString(isoString).getTime();
}

/** 暦日差（時分を捨てる）。大運の距離には使わない */
function getCalendarDaysDifference(date1, date2) {
  const day1 = Math.floor((date1.getTime() + JST_OFFSET_MS) / 86400000);
  const day2 = Math.floor((date2.getTime() + JST_OFFSET_MS) / 86400000);
  return day2 - day1;
}

/** 経過日数（小数を保持）。大運立運の距離に使う */
function getElapsedDays(date1, date2) {
  return (date2.getTime() - date1.getTime()) / 86400000;
}
```

`DateUtils.createDate` は `new Date(toJstEpochMillis(...))` とする（instantのみ。`getHours()` などローカル成分は使わない）。  
`isValidDate` は `daysInMonth` ベース（ローカル `Date` 不使用）。

### 4.4 大運開始年齢（確定・N-05）

```
birthInstant = createDate(y, m, d, h, mi)          // 時刻ありは t_corrected、なしは 12:00
termInstant  = 次節 or 前節（epoch 比較で選択。時分を使う）
elapsedDays  = Math.abs(getElapsedDays(birthInstant, termInstant))  // 小数日
ageFloat     = elapsedDays / 3
startAge     = round(ageFloat) または ceil(ageFloat)   // 既存の roundingMethod
startAge     = clamp(startAge, 0, 10)
```

- **禁止:** `getCalendarDaysDifference` を立運距離に使わない（同じ暦日内の時分が消える）
- 節の選択（次/前）は epoch 比較。距離は小数日。用途を混同しない

## 5. 出力オブジェクト

```ts
type TimeCorrectionResult = {
  applied: boolean; // 時刻入力ありなら true（補正量0でも true）
  input: { year: number; month: number; day: number; hour: number; minute: number };
  corrected: { year: number; month: number; day: number; hour: number; minute: number };
  offsetMinutes: number;
  longitudeOffsetMinutes: number;
  totalOffsetMinutes: number;
  prefecture: null | { code: string; name: string; longitudeEast: number };
  display: {
    statusText: string; // "適用"
    inputText: string;
    offsetText: string;
    longitudeText: string;
    correctedText: string;
  };
};
```

時刻なし時:

```ts
{ applied: false, reason: 'no_time' }
```

## 6. 節入り・大運との関係

- **時刻あり:** `corrected`（`t_corrected`）を年月柱の節入り比較および大運立運の出生時刻として使用する。立運距離は **`getElapsedDays`（小数日）**
- **時刻なし:** 本サービスは呼ばない。大運は入力年月日 **12:00**（V1.0踏襲）
- 子時モードの日+1はここでは行わない
