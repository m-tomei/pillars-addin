## 2. タスク分解（概要）

詳細は `11` を使う。ここは配置の要約のみ。

### P0
- マスタJSON、DataLoader、`addMinutes`/`addDays`、`toJstEpochMillis` / ISO offset保持、`getElapsedDays`、定数

### P1
- `TimeCorrectionService.js`
- TC-01〜08, TC-10〜14（**TC-09はP4**）

### P2
- `resolveDayPillarDate`、`calculateHourPillar` / `calculateFortune`、節入りを epoch 比較へ
- SM-01〜08、**ST-02, ST-03**、既存23時台テスト更新

### P3
- `calculateStartAge` / 節探索へ時分 + **`getElapsedDays`（小数日）**
- **GF-01〜04**（ST-01はP5）。P2と並行可（P0依存）

### P4
- HTML/CSS、FormRenderer、InputParser、InputManager
- 時差・子時ヘルプ文
- **TC-09**（±24:00 は InputManager）

### P5
- AppController（補正→命式→大運12:00フォールバック含む）
- `showResults(..., displayYear, { correction, shiMode })`
- **IX-01〜04、ST-01**、節気範囲外・マスタ初期化失敗

### P6
- 補正サマリ、PNG、`clear()` でサマリ消去

### P7
- `chrome-extension/package.json`、フッタ `1.5.0`
- `chrome-extension/docs/USER_GUIDE.md`
- `chrome-extension/docs/ALGORITHM.md`

### P8
- 全テスト緑、受入 UI-01〜09

## 3. 完了条件

1. 要件・詳細設計の確定項目を満たす
2. 時刻ありの大運は補正後時分、時刻なしは入力年月日12:00
3. `resolveDayPillarDate` が日柱・時干のみに効く
4. 東京 +19分、丸め `Math.round`
5. 単体・統合テストが通過する
6. PNGに補正情報と子時モードが含まれる
7. バージョン `1.5.0`
