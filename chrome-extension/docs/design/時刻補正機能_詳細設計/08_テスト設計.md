# 08. テスト設計

## 0. DateUtils（JST固定）

| ID | ケース | 期待 |
|----|--------|------|
| DU-01 | `toJstEpochMillis(1990,5,1,8,30)` | `Date.UTC(1990,4,1,8,30) - 9h` と一致 |
| DU-02 | `parseISOString('1990-05-01T08:30:00+09:00')` | DU-01 と同じ epoch（`+09:00` を削除しない） |
| DU-03 | `createDate` の `getTime()` | `toJstEpochMillis` と一致 |
| DU-04 | `getCalendarDaysDifference` | 同日0、翌日1。時分を捨てる。TZ非依存 |
| DU-05 | `getElapsedDays` | 12時間差は `0.5`。小数を保持。`(t2-t1)/86400000` |

## 1. 方針

- 補正は純粋な数値演算として単体テスト
- 子時・日跨ぎは FortuneCalculator
- 大運は時分反映を明示テスト
- 補正×子時の合成境界を統合テスト
- V1.0 回帰は「補正なし・非23時台」を中心

## 4. 節入り・大運

| ID | ケース | 期待 |
|----|--------|------|
| ST-01 | 節入り直前に補正で跨ぐ（P5統合） | 月柱/年柱が補正後側 |
| ST-02 | 補正なし・**非23時台** | V1.0 と同じ柱 |
| ST-03 | 数値JSTと節気ISOを epoch 比較 | 境界直前/直後の年月柱が環境TZに依存しない（P2） |
| GF-01 | 次節/前節は同一だが、時分差で `elapsedDays/3` の四捨五入境界を跨ぐ | 開始年齢が変わる（暦日差では変わらないケース） |
| GF-02 | `calculateStartAge` に時分が渡り、正午固定でない | API契約テスト |
| GF-03 | 子時+1日を大運に使わない | 23時台でも立運日付は `t_corrected` 当日基準 |
| GF-04 | 立運距離 | TZ非依存の epoch 差、かつ **小数日を保持**（整数暦日差と一致しないこと） |

## 5. 補正×子時の合成（P5統合）

前提: 入力に時差または経度補正を加え、`t_corrected` が目標時台になるケースを選ぶ。

| ID | 入力（例） | 補正後 | モード | 時支 | 日柱 | 年月柱 |
|----|------------|--------|--------|------|------|--------|
| IX-01 | 22:50 → 補正で23時台 | 当日 23:xx | `switch23` | 子 | **翌日**（人工+1） | `t_corrected`（当日23時台） |
| IX-02 | 23:50 → 補正で翌日0時台 | 翌日 00:xx | `switch23` | 子 | **補正後当日**（人工+1不要） | `t_corrected`（翌日0時台） |
| IX-03 | 22:50 → 補正で23時台 | 当日 23:xx | `switch00` | **亥** | **補正後当日** | `t_corrected`（当日23時台） |
| IX-04 | 23:50 → 補正で翌日0時台 | 翌日 00:xx | `switch00` | **子** | **補正後当日** | `t_corrected`（翌日0時台） |

IX-01/03 の年月柱は子時の人工+1日を使わない（23時台のまま節入り比較）。
