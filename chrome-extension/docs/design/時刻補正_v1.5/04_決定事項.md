# 04. 決定事項

要件定義の判断結果。レビュー（2026-08-13）反映後もすべて確定。

## 方法論

| 項目 | 決定 |
|------|------|
| 対象方式 | **四柱推命（子平法ベース）**。禄命法ではない |
| 通変星・日柱中心パイプライン | 既存どおり維持 |

## D: その他

| ID | 項目 | 決定 |
|----|------|------|
| D-1 | 夏時間（DST） | **非対応**（時差手入力で吸収） |
| D-2 | 子時 | **2モード**: `23時切替` / `0時切替` |
| D-3 | その他追加補正 | なし |

### 子時モード詳細

| モード | 時支 | 23時台の日柱・時干 |
|--------|------|-------------------|
| 23時切替 (`switch23`) | 23:00–00:59＝子 | 翌日（`resolveDayPillarDate`） |
| 0時切替 (`switch00`) | 00:00–01:59＝子、22:00–23:59＝亥 | 当日 |

既定・未送信: `switch23` / 定義外: 入力エラー

## レビューで追加確定した事項

| ID | 論点 | 決定 |
|----|------|------|
| R-P0-01 | 大運への時分反映 | **時分まで反映**。距離は `getElapsedDays`（小数日）。`calculateStartAge` と節入り探索APIに時分を追加 |
| R-P0-02 | 日柱日付関数名 | **`resolveDayPillarDate` に統一** |
| R-P0-03 | 子時+1日の適用範囲 | **日柱・時干のみ**。年月柱・大運は `t_corrected` |
| R-P1-01 | 丸め・東京表示 | `Math.round`、東京 **+19分** |
| R-P1-02 | 日時表現 | JST暦の数値年月日時分。OS `Date` TZ非依存 |
| R-P1-04 | 表示用生年 | 補正適用時は `t_corrected.year` |
| R-P2-02 | 子時不正値 | 未送信→`switch23`、定義外→エラー |
| R-P2-03 | 分欠落 | 時あり・分空 → **0分** |
| R-P2-04 | 不正都道府県 | InputManager でフォームエラー |
| R-P2-05 | 時刻なしサマリ | **1行表示**。配置順は詳細設計どおり |
| R-P2-06 | `applied` | 時刻入力ありなら `true`（補正量0でも内訳表示） |
| R-H-03 | 時刻未入力時の大運 | **入力年月日 12:00（V1.0踏襲）**。`t_corrected` は存在しない |
| R-H-01 | TC-09 責務 | 時差 ±24:00 は **InputManager**（P4）。サービスは範囲内前提 |
| R-M-07 | IX 合成境界 | `switch00` は IX-03（22→23）と IX-04（23→0）に分離 |
| R-N-01 | 節入り比較 | **JST epoch**。`toJstEpochMillis` と ISO offset保持。ローカルDate比較禁止 |
| R-N-02 | P2/P3依存 | P3はP0依存のみ。P2と並行可 |
| R-N-03 | ResultRenderer | P5でAPI配線、P6でDOM |
| R-N-04 | TC-02 | +19分かつ表示に `+19分` / `東京都` |
| R-N-05 | 大運距離 | **`getElapsedDays`（epoch差の小数日）**。暦日整数差は使わない |

## 確定スコープ再掲

- A: 地方平均時補正（明石135°、`Math.round`、固定マスタ）
- C: 時差手入力
- D: DSTなし、子時2モードあり
- 真太陽時: 不採用
- 影響: 時柱 + 節入り（年月）+ 大運立運（epoch小数日） / 子時+1日は日柱・時干のみ
- UI: 常時ON、PNGに補正情報・子時モード
- 時刻不明: 補正なし、サマリ1行、大運は入力年月日12:00
- 機能: 時刻補正＋子時モード / バージョン 1.5.0
