## 1. 結論

命式本体と病薬オプションの分離、`日干→月令→気象→主軸→損傷→病薬→喜忌` の順序、用神損傷を主病・気象を副病とする方針は参照資料と整合する。

一方、実装へ進む前に次の3点を解消する必要がある。

1. 提供資料には四病四薬の詳細判定、とくに「長」の発動条件と代表例がない
2. 月令×2.0、從重40%、気象差2.0/1.5は設計上のヒューリスティックで、資料例・反例による校正がない
3. UI受入テストに使う生年月日時・性別・期待四柱が固定されていない

これらを [06_実装計画と決定事項](../病薬表示オプション/06_実装計画と未決事項.md) の R-01〜R-03 として実装開始条件にした。

## 2. 修正した仕様上の問題

| 重要度 | 問題 | 修正 |
|--------|------|------|
| 高 | 上位仕様は気象を格局・用神より先とする一方、詳細フローは格局の後に気象を実行していた | `KishouAssessor` を日干・月令確定直後へ移動 |
| 高 | `diagnose` が位置引数維持とobject引数必須の二重定義だった | v2正規APIをobject引数に統一。位置引数は移行アダプタ限定 |
| 高 | 気象病の `disease.element` に不足側＝薬五行を入れる定義になっていた | 原因不明時は `null`、`causeElements` と `deficientElements` を分離 |
| 中 | 上位仕様では清濁が必須、詳細設計では初版見送りだった | 初版は `clarity: '不明'` 固定に統一 |
| 中 | アーキテクチャ文書が `ByoyakuCalculator` 原則変更なしとしていた | 月令ブースト・從重接続・気象／継善突合・バランス追加を明記 |
| 中 | 気象extremeを四病の独自値のように扱う余地があった | `fourDisease` は四値を維持し、気象は別診断として管理 |
| 中 | 気象診断を表示先頭にすると、既存大運吉凶がnullの病五行を参照しうる | 表示順と代表診断を分離し、null時の片側評価／スキップを契約化 |
| 中 | 合冲UIの扱いが未決だった | D-02=A。病薬の内部入力に限り、UIは表示しない |
| 中 | OFF時の受入が「非表示」しか確認せず、非実行を保証しなかった | optional calculatorが呼ばれないspy結合テストを追加 |

## 3. 資料との整合確認

### 整合している点

- [喜忌篇](../../../../資料/喜忌篇_初心者から中級者向け解説.md): 日干を主、月令を提綱、透干を先に見る順序
- [気象篇](../../../../資料/気象篇_初心者から中級者向け解説.md): 用神・病薬の前に寒暖燥湿など局全体を確認する方針
- [継善篇](../../../../資料/継善篇_初心者から中級者向け解説.md): 用神を傷つける要素を病候補とする方針
- [病薬説](../../../../資料/病薬説_初心者から中級者向け解説.md): 月令起点の從重、病と薬の所在・強弱・バランス

### 根拠が不足している点

- 病薬説資料は四病四薬の名称と次章への接続を示すが、四処方の詳細規則は扱っていない
- 数値ウェイト・閾値は資料中の定量値ではなく、実装可能にするための仮説である
- 清濁は資料上重要だが、件数だけの簡易判定では意味を狭めるため初版から外す

## 4. 確定した設計判断

| ID | 決定 |
|----|------|
| D-01 | 病薬OFFでは大運吉凶を実行しない。ONでは既存トグル用評価を維持 |
| D-02 | 合冲は内部利用のみ。合冲UIは出さない |
| D-03 | 格局・身旺弱は病薬セクションの補助情報として表示 |
| D-04 | 計算済みかつ入力有効ならスイッチ変更時に自動再計算 |
| D-05 | 初版はセッション内保持のみ |
| D-06 | デフォルトOFF |
| D-07 | 用神損傷を主病、気象を副病 |
| D-08 | 清濁は初版見送り、`不明` 固定 |
