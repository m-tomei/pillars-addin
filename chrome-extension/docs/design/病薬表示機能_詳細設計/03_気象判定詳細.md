# 03. 気象判定詳細（KishouAssessor）

| 文書ID | BYO-DD-03 |
|--------|-----------|
| 根拠 | `資料/気象篇_初心者から中級者向け解説.md` |

## 1. 目的

病薬・用神の前に、命式全体の **気象規模**を評価し、調候の方向を返す。初版の評価対象は寒暖・燥湿で、清濁は契約上のフィールドだけを残して `不明` とする。

## 2. 公開API

```text
KishouAssessor.assess(fortuneResult, options?) → KishouResult

KishouResult {
  temperature: '寒' | '涼' | '温' | '熱' | '中和'
  humidity:    '燥' | '中' | '湿'
  clarity:     '清' | '濁' | '不明'     // 初版は '不明' でも可
  severity:    'mild' | 'moderate' | 'severe'  // 偏りの強さ
  choukou: {
    direction: '温める' | '冷ます' | '潤す' | '燥す' | '整理' | 'なし'
    primaryElements: string[]   // 例: ['火'] / ['水'] / ['火','木']
    secondary: Array<{
      direction: '温める' | '冷ます' | '潤す' | '燥す'
      elements: string[]
      reason: string
    }>
  }
  scores: {
    fireEarth: number
    waterMetal: number
    wood: number
    // 内部デバッグ用
  }
  summary: string  // 表示用一言
  isExtreme: boolean
}
```

## 3. 判定アルゴリズム

### 3.1 月令ベース温度

| 月支 | baseTemp |
|------|----------|
| 亥, 子, 丑 | 寒 |
| 寅, 卯, 辰 | 温 |
| 巳, 午, 未 | 熱 |
| 申, 酉, 戌 | 涼 |

### 3.2 五行補正スコア

柱ウェイト適用後の五行分布を用い:

```text
heatScore  = 火 + 土×0.5
coldScore  = 水 + 金×0.5
dryScore   = 火×0.5 + 土
wetScore   = 水
```

シフト規則（たたき台・レビュー対象）:

```text
if heatScore - coldScore >= 2.0: temperature を熱側へ1段シフト
if coldScore - heatScore >= 2.0: temperature を寒側へ1段シフト
（寒←涼←中和←温←熱 のスケール上で移動。上限でクリップ）
```

段の定義:

```text
寒 < 涼 < 中和 < 温 < 熱
```

月令ベースが「温／涼」のとき、補正で「中和」へ戻ることも許容。

### 3.3 燥湿

```text
if dryScore - wetScore >= 1.5 → 燥
else if wetScore - dryScore >= 1.5 → 湿
else → 中
```

### 3.4 清濁（初版方針）

**決定（D-08-A）:** 初版は `clarity: '不明'` 固定。清／濁の簡易推定は行わない。

清濁は単なる件数判定にすると資料の「流れの整然さ」を誤って表すおそれがある。採用する場合は別仕様として根拠、反例、fixtureを追加する。

### 3.5 偏りの重症度

```text
temperature ∈ {寒,熱} かつ |heatScore-coldScore| >= 3 → severe
temperature ∈ {寒,熱} または humidity ∈ {燥,湿} の極端 → moderate
それ以外 → mild
isExtreme = severity !== 'mild'
```

### 3.6 調候方向

| 条件 | direction | primaryElements |
|------|-----------|-----------------|
| temperature=寒（または涼かつ cold優位） | 温める | ['火']、通関必要なら +['木'] |
| temperature=熱（または温かつ heat優位） | 冷ます | ['水']、生水に +['金'] |
| humidity=燥 かつ temperature が寒でない | 潤す | ['水'] |
| humidity=湿 かつ temperature が熱でない | 燥す | ['土']（必要なら火） |
| clarity=濁 | 整理 | （継善の破と合流。要素は空でも可） |
| 中和かつ燥湿中 | なし | [] |

競合時の優先:

```text
temperature の調候 > humidity の調候 > 整理
```

両方必要なら温度を主方向、湿度を `secondary[]` に方向名付きで保持する。木・金などの通関／生助は同じ方向の `elements` に含め、湿度の副方向と混同しない。

## 4. 病薬への受け渡し

`KishouResult.isExtreme === true` のとき:

```text
kishouDisease = {
  name: `気象偏枯（${temperature}/${humidity}）`,
  element: null,  // 害をなす一五行を確定できない場合
  causeElements: string[],       // 例: 寒で水勢が原因なら ['水']
  deficientElements: string[],   // 例: 温める必要があれば ['火']
  tenGod: null,  // 気象病は十神固定しない
  source: 'kishou'
}
kishouMedicine = {
  name: `調候（${direction}）`,
  elements: choukou.primaryElements,
  source: 'kishou'
}
```

`deficientElements` は薬候補であり、`disease.element` へ代入しない。これにより「病の五行」と「不足している薬の五行」の意味が逆転するのを防ぐ。

## 5. 資料実例との期待対応

### 例1: 冬月・丁火・水金多

| 項目 | 期待 |
|------|------|
| temperature | 寒 |
| humidity | 湿寄り |
| direction | 温める |
| primary | 火（＋木） |

### 例2: 夏月・庚金・火土多

| 項目 | 期待 |
|------|------|
| temperature | 熱 |
| humidity | 燥 |
| direction | 冷ます／潤す |
| primary | 水 |

### 例3: 春月・甲木多・金弱

| 項目 | 期待 |
|------|------|
| temperature | 温 |
| 備考 | 「伸びすぎ」は從重・旺側で扱い、気象は中〜温 |
